# 수익 구조와 광고 원칙

상태: 설계 초안 · 법률 검토 전
시안: 캔버스 '결정점' 페이지 `F3Loop.dc.html` (함께 탭, 같은 길 방, 나 · 설정)
관련: `docs/foundation/fevio-2.md` §1-3, §1-5, `docs/specs/together-and-coordinator.md`

## 1. 수익원

| 순서 | 수익원 | 누가 내나 | 비고 |
|---|---|---|---|
| 1 | 병원 구독 (활성 주기 기준) | 병원 | 주 수익. 병원 운영 효율(`docs/specs/plan-handoff.md`)로 정당화 |
| 2 | 생활 도움 광고 | 광고주 | 함께 탭과 커뮤니티 방에만. 노출 상한 있음 |
| 3 | 제휴 수수료 | 제휴사 | 귀가 택시, 보냉 파우치처럼 일정에 실제로 필요한 생활 서비스 |

하지 않는 것:
- 데이터 판매
- 개인을 식별할 수 있는 정보를 광고주에게 넘기는 것
- 의료·시술·병원·한의원·의약품 광고
- 효능을 내세우는 건강기능식품 광고
- 임신 성공을 암시하는 광고
- 결과 화면의 판매·업셀

## 2. 어디에 나오나

| 화면 | 광고 | 이유 |
|---|---|---|
| 함께 › 지원 › 생활 도움 | 카드 1장, '광고' 표시, 숨기기 | 생활을 돕는 영역이라 자연스럽다 |
| 같은 길 › 방 안 글 목록 | 글 2개 뒤 1장, '광고' 표시 | 방 주제에 맞춘 일반 광고 |
| 오늘, 일정, 커튼 대화, 투약, 트리거, 진료 뒤 계획 카드 | 없음 | 실행과 안전의 화면 |
| 배우자 화면 | 없음 | 환자가 공유한 정보로 광고하지 않는다 |
| 결과·판정 화면, 결과 보호 중 | 없음 | 기존 결정(`fevio-2.md`) |

## 3. 맞춤의 범위

- **기본은 일반 광고**다. 내 정보를 쓰지 않는다.
- **'일정에 맞춘 생활 광고'는 사용자가 나 · 설정에서 켤 때만 쓴다.** 날짜만 앱 안에서 쓰고, 병원·투약 정보는 광고주에게 가지 않는다.
  - 예: 채취 확정 → "월 07:30 · 채취 끝나고 귀가 택시 미리 잡기 · 진정 뒤에는 직접 운전하지 않아요"
  - 예: 자극 중 → "주사 펜 들고 다닐 때 · 휴대용 보냉 파우치"
- 광고주에게 가는 것은 집계된 노출 수와 클릭 수뿐이다.
- 노출 상한은 화면당 1장이다. '숨기기'를 누르면 그 자리에서 사라진다.

## 4. 커뮤니티 위치

- 함께 탭을 두 갈래로 나눈다: **지원**(지원 제도, 생활 도움) / **같은 길**(커뮤니티).
- 배우자 공유는 나 · 설정에 있으므로 함께 탭에 다시 보여 주지 않는다.
- 오늘 타임라인의 결정점 행에 "같은 갈림길 38명" 칩을 둔다. 누르면 그 방으로 바로 간다. 기다림이 생기는 바로 그 자리에서 커뮤니티로 들어가는 길이다.

## 5. 법률·운영 검토가 필요한 것 (출시 전)

1. 건강 관련 정보를 광고 맞춤에 쓸 때의 별도 동의 (개인정보보호법의 민감정보 규정). 날짜만 앱 안에서 쓰는 지금 구조가 여기에 해당하는지.
2. 광고 표시 방식 (표시광고법, 플랫폼 광고 표시 지침).
3. 커뮤니티 안 광고와 업종 제한. 의료광고 사전심의 대상과 건강기능식품 광고 심의 대상은 처음부터 받지 않는다.
4. 병원 구독 계약에서 광고를 끌 수 있게 할지 (병원별 설정).
5. 광고가 병원 신뢰를 떨어뜨리는지. 시범 병원에서 광고 끔과 켬을 비교해야 한다.

## 6. 아직 모르는 것

- 활성 주기당 광고·제휴 수익이 운영비를 얼마나 덮는지. 주기가 짧고(수 주) 사용자 수가 병원 규모에 묶여 있어 광고만으로는 작을 수 있다. 수익의 중심은 병원 구독으로 둔다.
- 사용자가 일정 맞춤 광고를 켤 비율.

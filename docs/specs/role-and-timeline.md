# 하나의 앱, 두 역할 · 마일스톤 타임라인

상태: 설계 · 시안 반영 (캔버스 '결정점' `F3Loop.dc.html`)
관련: `src/types/cycle-event.types.ts`(IvfPhase), `src/domain/cycle-state-machine.ts`(reduceCycleState), `docs/foundation/agent-operations.md`

## 1. 배우자는 별도 앱이 아니라 같은 앱의 '배우자 역할'이다

- 화면, 컴포넌트, 데이터 생성기는 하나만 둔다. 탭(일정 | 오늘 | 함께), Fevio, 나가 모두 같다.
- 바뀌는 것은 역할(`role`)과 환자가 정한 공유 범위(`shareScope`)뿐이다. 이 두 값이 기능을 켜고 끈다.
- 새 기능은 아래 표에 한 줄을 더하는 것으로 끝나야 한다. 역할마다 따로 화면을 만들지 않는다.

| 기능 | 환자 | 배우자 | 이유 |
|---|---|---|---|
| 오늘 타임라인 | 전체 | 같은 생성기 · 공유 범위로 거름 | 한 번만 만든다 |
| 투약 시각·용량 | 보임 | `flow_doses`일 때만 "서연 21:00 · 주사 2개" | 환자가 정함 |
| 배아·검사 숫자 | 보임 | 환자가 '숫자도 보이기'를 켰을 때만 | 민감 정보 |
| 진료 뒤 계획 카드 | 보임 · '확인했어요' | 읽기만 · "서연 확인함/확인 전" | 확인은 환자 한 번 |
| 투약 '맞았어요' | 가능 | 없음 | 기록은 한 사람(이중 기록 방지) |
| 일정 (주간) | 전체 | 같은 화면 · 투약은 공유 범위에 따라 | |
| 방문 시간 변경 요청 | 병원이 허용한 방문만 | 없음 | 병원에 두 번 들어가지 않게 |
| Fevio 대화 | 단계별 질문 · 담당 코디네이터 · 몸이 불편해요 | 단계별 질문 · "서연에게 물어보기" | 배우자 질문은 병원으로 가지 않는다 |
| 커뮤니티 | 전체 | 같은 화면 · 기본 주제 '배우자' | |
| 커뮤니티 사진 첨부 | 가능 | 가능 | 약 봉투·결과지처럼 글자가 있는 사진은 이름·번호를 자동으로 가린다. 결과지를 올리면 '코디네이터에게도 보여 줄까요?'를 먼저 묻는다 |
| 지원(보조금) · 이번 주 준비 | 보임 · 제휴 줄 포함 | 보임(읽기) · 제휴 줄 없음 | 부부가 함께 아는 정보. 배우자 화면에는 광고 없음 |
| 나 · 설정 | 공유 범위, 알림, 광고 | 알림만 · 공유 범위는 "서연이 정해요" | |
| 병원 콘솔에 남는 것 | 환자 행동만 | 없음 | 병원 숫자(재확인, 확인 단계)가 부풀지 않게 |

배포 측면에서도 바이너리는 하나다. 역할은 계정의 `care_memberships.role`(기존 `src/domain/care-os-architecture.ts`)에서 오고, 기능 표는 서버가 내려주는 설정 버전으로 관리한다. 기능을 끄고 켤 때 앱을 다시 배포하지 않는다.

## 2. 오늘 타임라인 = 마일스톤 틀 × 원장 이벤트 × 현재 단계

손으로 쓴 문장 목록이 아니다. 세 가지를 합쳐 만든다.

1. **마일스톤 틀 (앱 기본값, 병원 설정으로 덮어쓰기 가능)**: 주기 시작 → 과배란 주사 → 트리거 → 채취 → 수정·배양 → 이식 또는 동결 → 판정 피검사. `IvfPhase`를 이 일곱 묶음으로 매핑한다. 동결 이식 주기용 틀은 따로 둔다.
2. **원장 이벤트**: 확정된 진료·결정·투약 기록(`docs/foundation/agent-operations.md`의 사실 층).
3. **현재 단계**: `reduceCycleState`가 계산한 확정 단계.

화면 규칙:

| 마일스톤 위치 | 모양 | 내용 |
|---|---|---|
| 지난 단계 | ✓ 한 줄 | 날짜 + 요약 (예: 과배란 주사 · 11.13–20 · 주사 8일 · 검사 3번) |
| 지금 단계 | ● | 이 단계의 지난 진료들(작게) → 지금 줄 → 다음 결정점(◇, 갈래 포함) |
| 다음 단계, 날짜 확정 | ■ | 확정 시각 (예: 월 07:30 채취) |
| 다음 단계, 범위만 있음 | ○ + 빗금 띠 | 병원 프로토콜이 계산한 범위 (예: 빠르면 월 · 늦으면 수) |
| 그 뒤 | ○ | "날짜 미정" |

- 일곱 마일스톤은 항상 보인다. 그래서 처음 시술받는 사람도 전체 길과 지금 위치를 같이 본다.
- 검사를 한 번 더 받으면 지금 단계 안에 진료 줄이 하나 늘 뿐이다. 마일스톤은 그대로라서 뒤처져 보이지 않는다.
- 배우자 화면은 같은 함수에 `{ partner: true, share, lab }`을 넘겨 만든다.

## 3. 구현 순서

1. `packages/domain/timeline.ts`: 마일스톤 틀, `buildTimeline(state, ledger, { role, share })`. 순수 함수와 스냅샷 테스트.
2. `IvfPhase` → 마일스톤 매핑 테스트(21개 단계 전부).
3. 역할 기능 표를 설정 산출물(`ConfigArtifact`)로 만들고, 앱은 그 표만 읽는다.
4. RLS: 배우자 계정은 `partner_view` 투영만 읽는다(기존 원칙 유지).

## 4. 아직 모르는 것

- 병원마다 마일스톤 이름과 순서가 얼마나 다른지(예: '난자 채취' vs '채취', 동결 주기).
- 배우자가 '서연에게 물어보기'를 실제로 쓸지, 아니면 그냥 메신저로 묻는지.
- 배우자 화면에서 마일스톤 전체를 보여 주는 게 부담인지. 그렇다면 공유 범위 '흐름만'에서도 지금 단계와 다음 결정만 보이게 줄일 수 있다.

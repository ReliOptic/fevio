# 병원 운영 대시보드

상태: 탐색 시안 · 실제 병원 검증 전
시안: 캔버스 '결정점' 페이지 `F3Loop.dc.html` 오른쪽 데스크톱 화면
관련: `docs/specs/visit-scheduling.md`, `docs/specs/decision-points.md`, `docs/foundation/agent-operations.md`

## 1. 환자 화면과 문법이 다르다

| | 환자·배우자 화면 | 병원 화면 |
|---|---|---|
| 역할 | 과정을 설명한다 | 변화를 발견하고 처리한다 |
| 중심 | 타임라인 (지나온 길, 지금, 다음 갈림길) | 업무 목록 (누가 무엇을 해야 하나) |
| 시간 | 날짜 감각, 가능 범위 | 마지막 반영 시각, 방금 바뀐 것 |
| 달력 | 병원이 정하는 날은 빗금 띠 | 자원 배정표 (확보 / 확정 / 조건부 / 넘침) |

## 2. 첫 화면

1. **방금 바뀐 것 (왼쪽)**: 환자 요청, 의료진 결정, 직원 처리가 한 줄씩 쌓인다. 각 줄에 효과가 붙는다(예: "월·화 채취 조건부 −1 · 목 +1 · 시간 배정 +1"). 누르면 그 행이 열린다.
2. **업무 목록 (가운데)**
   - 상태는 다음에 움직일 사람이 드러나게 쓴다: 시간 배정 필요, 환자 회신 대기, 검사 결과 대기, 연구실 확인 필요, 응답 필요, 확정. '대기' 하나로 뭉뚱그리지 않는다.
   - 좁히기: 오늘 / 이번 주, 담당팀(코디네이터 · 의료진 · 연구실), 상태 칩(개수 포함).
   - 왼쪽 메뉴의 '방문 요청 6'을 누르면 그 여섯 건이 바로 나온다.
   - 교대 직후에는 아무 행도 선택되어 있지 않다. 옆 패널이 "가장 먼저 처리할 일"(응답 필요, 다음으로 시간 배정 필요)을 한 건 보여 준다.
3. **처리 패널 (오른쪽)**: 목록을 떠나지 않고 행 하나를 처리한다.
   - 보이는 것: 환자 희망 시간(받은 시각 포함), 병원 허용 범위, 기존 예약(변경 요청이면 유지 표시), 20분 단위 초음파실 남은 자리, 판독·간호 담당.
   - 희망 안의 자리는 바로 '배정'된다. 희망 밖은 '제안'만 된다(환자가 수락해야 확정).
   - 희망 시간대가 꽉 찼으면 그 사실을 먼저 알려 준다.
4. **자원 배정 (아래)**
   - 월 오전 초음파실(시간대별)과 다음 주 채취실·배아연구원(요일별)을 나눠 보여 준다.
   - 칸의 모양으로 구분한다: 검정 = 확정, 빗금 = 조건부(검사 결과에 따라), 빈 칸 = 여유, 빨간 테두리 = 넘침.
   - 숫자도 함께 쓴다: "확정 n · 조건부 n / 확보 n", "부족 n".

## 3. 세는 규칙

- 조건부 채취 수요는 가능한 날마다 칸에 보인다(그날 준비 상한). 주간 합계에서는 사람 기준 1명이다: "확정 3 · 조건부 5명 (날짜 미정 · 사람 기준)".
- 초음파 조건부 수요의 경우:
  - 희망이나 제안 시간이 한 시간 안에 들어가는 사람만 그 시간대에 넣는다.
  - 여러 시간대에 걸치거나 아직 시간을 안 보낸 사람은 시간대에 넣지 않고 따로 표시한다("시간대에 넣지 않은 조건부 1명").
- 병원 쪽 '가능'과 '조건부'는 환자에게 확정으로 나가지 않는다. 환자에게는 확정된 방문만 보인다.

## 4. 실시간성은 한 건의 변화로 보인다

| 시각 | 이벤트 | 화면에서 바뀌는 것 |
|---|---|---|
| 10:32 | 의료진: P-0419 월 추가 초음파 결정 | P-0419 행이 같은 자리에서 '검사 결과 대기'에서 '시간 배정 필요'로 바뀐다. 다음 주 채취의 월·화 조건부가 −1, 목이 +1 되고 변경 배지가 붙는다. 환자 앱에는 월 오전 검사와 '시간 정하기'가 생긴다 |
| 10:41 | 환자: 월 09:00–10:00 가능 | 새 행을 만들지 않는다. 같은 행에 희망 시간과 '10:41 갱신'이 붙는다. 초음파 09시 칸에 조건부 1이 들어간다 |
| 10:43 | 코디네이터: 09:20 배정 | 행이 '확정 09:20'이 된다. 09시 칸은 확정 6/6이 된다. 환자 오늘 타임라인 칩이 '09:20 확정'이 되고, 배우자 화면에 '월 11.23 09:20 · 확정'이 뜬다 |

- 새 정보가 들어와도 목록 순서는 바뀌지 않는다. 행은 제자리에서 상태만 바뀐다.
- 열어 둔 행과 입력 중인 메모는 그대로 남는다. 필터 때문에 사라질 행은 '필터 밖 · 열어 둔 행'으로 남긴다.
- 상단에 '연결됨 · 마지막 반영 10:43:12'를 표시한다.
- 연결이 끊기면 다음과 같이 된다.
  - 상단 표시가 '연결 끊김 · 10:43:12 이후 변경이 반영되지 않았어요'로 바뀐다.
  - 화면 전체가 흐려지고 배정과 제안 버튼이 잠긴다.
  - 그사이 들어온 변경은 다시 연결될 때 순서대로 반영되고, "밀린 변경 n건 반영"이 한 줄 남는다.
- 시연용 합성 이벤트(10:32 결정, 10:41 환자 희망, 연결 끊기, 처음으로)는 제품 화면 밖의 점선 띠에 둔다. 환자 폰에서 직접 시간을 보내도 같은 이벤트가 된다.

## 5. 두 가지 기준

- **교대 직후 들어온 직원이 한 건을 바로 찾아 끝낼 수 있는가.** 옆 패널의 "가장 먼저 처리할 일" → 행 열기 → 추천 시간 확인 → '배정'. 네 번 누르면 끝나고, 환자 앱 반영도 같은 순간에 일어난다.
- **연구실 담당자가 다음 주 준비량의 변화를 읽을 수 있는가.** 자원 배정 아래 줄에서 요일별 확정·조건부·확보·부족을 보고, 변경 배지(예: "−1 · 10:32")로 교대 뒤 무엇이 바뀌었는지 읽는다.

## 6. 아직 모르는 것

1. 실제 코디네이터가 하루 처리하는 건수와 종류. 상태 다섯 가지로 충분한지.
2. 초음파실 수와 20분 단위가 병원마다 어떻게 다른지(설정으로 받아야 함).
3. 병원 예약 시스템과 동시에 확정해야 하는 문제. 이중 입력이 남아 있으면 '배정' 한 번으로 끝나지 않는다.
4. 여러 직원이 같은 행을 동시에 열었을 때의 처리. 행 잠금을 걸지, 나중에 저장한 쪽을 막을지.
5. 연구실이 실제로 쓰는 준비 단위. 채취 건수인지, 배양 접시나 인큐베이터 칸인지.

# 핵심 장면: 병원이 정하고, 환자는 최신 계획을 확인한다

상태: 피칭 핵심 장면 · 현장 검증 전
시안: 캔버스 '결정점' 페이지 `F3Loop.dc.html` (환자 ③ 단계와 병원 '운영 현황')
대체하는 것: `docs/specs/visit-scheduling.md`의 '요청 → 병원 제안 → 환자 수락'을 핵심 장면에서 뺀다. 그 흐름은 병원이 시간 조정을 허용한 방문에만 쓰는 예외 기능으로 남긴다.

## 1. 왜 바꾸나

- 병원은 이미 진료실이나 수납 창구에서 다음 내원을 잡아 준다. Fevio에서 희망 시간을 다시 받고 간호사가 승인하면, 간호사에게 요청함이 하나 더 생긴다.
- 확인된 사례:
  - 검사 뒤 의료진이 당일 결과를 검토하고, 간호사가 다음 계획을 전화로 알린다(MUHC). 내원 중에 계획을 안내하고, 바뀌면 전화하기도 한다(미국 CRM).
  - 검사를 여러 번 받는다고 해서 환자가 매번 직접 예약하는 것은 아니다.
- 국내 난임전문병원 간호사 면담(박점미·신나연 2020, 8명)에서 나온 부담은 '진료실 밖에서 다시 설명하는 시간'과 '오전 진료가 몰릴 때 상담 시간 부족'이었다. 이 연구는 예약 변경 건수를 재지 않았다.
- 버몬트대 난임팀 보고서에서는 전화의 약 절반이 초음파·외래 예약과 관련됐다. 하지만 신규 예약과 변경을 나누지 않았다. 그래서 국내 간호사에게 재예약이 큰 부담이라는 근거는 아직 없다.

## 2. 환자 장면 (귀가 후)

진료 뒤 의료진이 다음 내원과 투약 계획을 정하면, 환자 앱 '오늘' 타임라인 안에 **오늘 진료 뒤 계획** 카드 한 장이 들어간다. 자리는 지금 단계의 지난 진료 바로 다음, 다음 결정점 앞이다. 타임라인 위에 떠서 내용을 가리지 않는다.

| 줄 | 예 | 모양 |
|---|---|---|
| 다음 내원 (언제 다시 가나) | 월 11.23 09:20 · 초음파·피검사 | 확정 (회색 바탕) |
| 그때까지 (무엇을 하나) | 주사 그대로 · A 150 · B 75 · 매일 21:00 | 확정 (회색 바탕) |
| 아직 안 정해짐 (무엇이 열려 있나) | 채취일 · 월 검사 뒤 정해져요 | 빗금 |

- '확인했어요'를 누르면 카드는 그 자리에서 한 줄("오늘 진료 뒤 계획 · 월 09:20 내원 ✓")로 접힌다.
- 일정 탭에는 '다음 내원' 한 장만 둔다. 병원이 정한 시간이고, 내 캘린더에 '개인 일정'으로 들어간다. 시간 고르기 칩은 없다.
- 커튼의 미리 준비한 질문은 계획에 대한 재확인이다: "주사 용량은 그대로예요?", "채취는 언제쯤일까요?". 답은 병원이 정한 오늘 계획에서 한다.
- 시간을 바꿔야 할 때("월요일 시간을 바꿔야 해요")는 코디네이터에게 사정을 전하는 데서 끝난다. 바뀌기 전까지 기존 예약은 그대로다.
- 배우자 화면은 공유 범위 안에서 같은 다음 내원을 '병원 확정'으로 본다.

## 2-1. Fevio 대화의 미리 준비한 질문

미리 준비한 질문은 고정 메뉴가 아니다. 환자의 지금 상태에서 만든다.

- **질문을 만드는 재료:** 지금 단계, 다음 투약까지 남은 시간, 병원이 보낸 최신 계획, 아직 안 정해진 것, 공유 범위.
- **고르는 기준:** 간호사가 진료실 밖에서 다시 설명하게 되는 순간(박점미·신나연 2020)을 고른다. 답은 병원 처방, 병원 계획, 병원 승인 자료에서만 하고, 카드에 출처를 붙인다. 그 밖의 질문은 코디네이터에게 넘긴다.
- **맨 위 표시:** 커튼 맨 위에 "지금 서연님 · 처방 v2 · 11.17 기준"과 상황 칩(예: 21:00 주사까지 2:48, 토 08:30 검사, 채취일 미정)을 둔다. 에이전트가 무엇을 근거로 돕는지 먼저 보이게 하려는 것이다.
- **뺀 것:** "병원에서 전화를 받았어요", "처방이 바뀌었어요"는 뺐다. 병원이 계획을 보내는 구조에서 환자에게 전달자 역할을 맡기기 때문이다. 사진·문자 넣기는 입력창의 + 로 남긴다.
- **단계별 질문:**

| 단계 | 미리 준비한 질문 |
|---|---|
| 목 저녁 (자극 7일째) | 오늘 밤 주사, 뭘 얼마나 맞아요? / 토요일엔 몇 시까지 뭘 챙겨 가요? / 채취는 언제쯤이에요? / 민준에게 어떻게 설명하죠? |
| 투약 직전 | 새 펜 준비 순서 다시 보기 / A랑 B는 따로 맞아요? / 시간에 못 맞출 것 같아요 / 민준이 대신 놓아 줘도 돼요? |
| 진료 뒤 계획 받음 | 주사 용량은 그대로예요? / 월요일엔 몇 시까지 가요? / 채취는 언제쯤일까요? / 월요일 시간을 바꿔야 해요 |
| 트리거 날 | 트리거는 정확히 몇 시예요? / 금식은 언제부터예요? / 채취 날 뭘 챙겨요? / 민준은 뭘 준비해요? |
| 연구실 | 배아 소식은 언제 와요? / 목요일엔 뭐가 정해져요? / 숫자는 누가 볼 수 있어요? / 이식 날 함께 가도 돼요? |

- **"민준에게 어떻게 설명하죠?"의 답:** 설명 문구를 대신 써 주지 않는다. 대신 "민준 님 화면에는 이미 이렇게 보여요"라며 공유 범위 안의 화면을 보여 준다. 환자가 집에서 다시 설명하는 일을 줄이려는 것이다. 공유가 꺼져 있으면 켜는 곳을 알려 준다.
- **병원 쪽 집계:** 계획에서 답한 재확인은 병원 운영 현황의 '오늘 들어온 연락'에 'Fevio가 병원 계획으로 답함'으로 쌓인다.

## 3. 병원 장면: 운영 현황 (환자별 백로그가 아니라 프로세스)

1. **오전 모니터링 흐름 (맨 위)**: 검사 완료 → 판독·결정 → 환자에게 계획 안내 → 환자가 계획 확인.
   - 단계마다 표시하는 것: 인원, 점(환자 1명 = 점 1개), 단계 소요 시간.
   - 예: 검사→결정 중앙값, 안내까지 Fevio 1분 · 전화 13분, 30분 넘긴 안내.
   - 환자 목록은 단계를 눌렀을 때만 옆에서 열린다.
   - '확인 표시 없음'은 환자가 누르지 않았다는 뜻일 뿐이다. 이해하지 못했다고 추정하지 않는다.
2. **오늘 들어온 연락**: 이미 안내한 내용 재확인 / 시간 변경 요청 / 증상·몸 상태 / 기타로 나눈다. 각 항목마다 Fevio가 병원 계획으로 답한 건수와 간호사가 처리한 건수(분 환산)를 따로 보인다.
3. **사람이 볼 것**: 예외만 보인다.
   - 앱을 쓰지 않아 전화로 알려야 하는 안내
   - 병원이 조정 가능하게 연 방문의 변경 요청
   - 계획에 없는 질문
   - 증상 문의
4. **다음 주 준비**: 초음파실(확정 내원)과 채취실·배아연구원(확정 / 조건부). 조건부 수요는 주간 합계에서 사람 기준으로 센다. 오전 결정이 들어올 때마다 바뀐 칸에 변경 배지가 붙는다.

실시간성은 한 건으로 보인다. 10:32 의료진이 P-0419를 '하루 더 · 월 09:20'으로 결정하면 다음이 함께 일어난다.
- 판독·결정과 안내가 각각 +1 된다.
- 월 초음파 확정 +1, 월·화 채취 조건부 −1, 목 +1이 된다.
- 환자 앱에 계획 카드가 뜬다.
- 환자가 '확인했어요'를 누르면 확인 단계 +1, 커튼에서 재확인하면 'Fevio가 답함' +1이 된다.

## 4. 병원이 얻는 것 (가설)

| 가설 | 재는 법 |
|---|---|
| 결정 → 환자 안내 시간이 줄어든다 | 결정 시각과 안내 시각의 차이. Fevio로 안내한 것과 전화로 안내한 것을 나눈다 |
| '다시 설명'하는 연락이 줄어든다 | 재확인 연락 중 Fevio가 병원 계획으로 답한 비율, 간호사 처리 건수와 분 |
| 다음 주 연구실·채취실 준비가 빨라진다 | 조건부 수요가 확정되는 시각과 인력 확정 시각 |

화면의 숫자는 모두 시연용 가짜 값이다.

## 5. 현장에서 먼저 물을 것

> 지난주 초음파 후속 연락 중, 환자가 시간을 바꿔 달라는 연락과 이미 안내한 내용을 다시 확인하는 연락이 각각 몇 건이었나요? 각각 누가 처리했고 몇 분 걸렸나요?

- 재확인이 많으면: 이 장면(계획 카드 + 계획 근거 답변)이 맞다.
- 변경이 많고 병원이 조정 가능한 방문이라면: 예외 기능(`visit-scheduling.md`, 저장·동시성 검증 끝)을 켤 근거가 된다.
- EMR과 문자로 이미 잘 되고 있거나, Fevio에 한 번 더 입력해야 한다면: 안내 기능도 도입 이유가 약하다. 이 경우 병원 시스템 연동(입력 0회)이 먼저다.

## 6. 아직 모르는 것

1. 결정과 계획을 Fevio에 넣는 사람과 시점. 진료실, 수납, 간호 중 누가 입력해야 이중 입력이 생기지 않는지.
2. 환자가 '확인했어요'를 누를 동기. 누르지 않아도 병원 업무가 늘지 않아야 한다.
3. 계획 근거 답변의 범위. 계획에 없는 질문은 반드시 사람에게 넘어가야 한다.
